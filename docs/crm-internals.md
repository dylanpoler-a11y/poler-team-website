## Flash live-coach panel (2026-06-19)

**Flash live-coach panel** (added 2026-06-19): the lead panel has a "🎯 Coach en vivo" button (`#panel-coach-start` in `crm.html`) that lazy-loads **Flash** (the AI sales-call coach, `~/business/saas-portfolio/clairvo-clone`, on Vercel project `flash-coach`) as an iframe at `flash-coach-tan.vercel.app/embed?leadId=&key=[&bucket=leadgen]&rep=<currentAgent.name>`, pre-locked to the open lead (`&rep=` since 2026-09-10 — Flash stamps its deterministic notes/reminders "Rosa llamó — …" when Rosa is logged in; letters-only ≤30 chars, else "Kevin"); ⛶ (`#panel-expand`) widens the panel (`.panel-expanded`). `crm.js`: `openFlashCoach`/`getFlashConfig`/`resetCoachSection`/`togglePanelExpand` + an **origin-checked** `handleFlashMessage` (the `message` listener) that, on `flash:call-ended`, appends the call summary to the lead via `/api/agent/log-note` (agent="Flash Coach"). **Post-call writes (2026-07-01, server-primary since 2026-07-03):** the note is a CALL SUMMARY per the `crm-note-format` skill (headerless `Convo:`/`Next:` bullets from the judge's `crmConvo`/`crmNext`) — NEVER Flash's coaching critique/score. Since 2026-07-03 **Flash's SERVER writes the note + follow-up reminder itself** right after judging (its `deliverToCrm` → `/api/agent/log-note` + `/api/create-reminder`, Bearer `AGENT_API_TOKEN`) — the old postMessage-only chain silently lost the note whenever the iframe died during the ~20s judge wait or the run route 500'd (Alfredo Carvajal). `handleFlashMessage` now reads `data.noteLogged`/`data.reminderCreated`: when set it only refreshes the panel; when false it falls back to writing from the browser as before (dueAt judged from the call's outcome; none for wrong-number/dead calls), then `loadReminders()` + re-renders. Flash's server also auto-activates the lead's PROPERTY ALERTS from the call's buy-box (`/api/agent/update-alerts`, Weekly/5) — only when the lead has no active alert profile yet, so it never clobbers a hand-tuned one; a separate LAND budget becomes a second profile via the `profiles` array (never blended into the house range). **Alert engine (2026-07-03):** profile type `Land` queries Bridge `PropertyType "Land/Boat Docks"` (subtypes Residential + Agriculture, residential-only filters stripped — `lib/alert-search.js`); multi-profile leads get ≥1 slot per profile in the capped email (fairness rule); email cards show lot size when a listing has no living area; Land checkbox in the CRM panel + `/preferences`. **Flash reminder policy (Kevin 2026-07-03):** judged cadence; ambiguous-but-real call → default 5 days; due 10:00 AM ET; a new Flash reminder auto-COMPLETES the lead's prior pending "Flash Coach" reminders (Sammy's + manual ones untouched). The iframe token comes from NEW gated `api/flash-config.js` (keeps `FLASH_EMBED_TOKEN` out of the public `crm.js`). Vercel env: `FLASH_EMBED_TOKEN` (must be byte-identical to the `flash-coach` Vercel project's value — set with `printf`, never `echo`; a trailing `\n` breaks the SHA-256 match and bounces the iframe to Flash's password gate, see 2026-06-22) + `FLASH_BASE_URL` (= `https://flash-coach-tan.vercel.app`). Flash owns the coaching brain; the CRM only launches it + logs the note. **Call recording (2026-06-24):** on a `flash:recording` postMessage, the same origin-checked `handleFlashMessage` saves the call audio to the lead via NEW `api/agent/save-recording.js` → the NEW `Flash Recordings` multilineText field on Leads (JSON `[{url,recordedAt,durationSec,callId}]`; audio lives on Vercel Blob, host-validated). `get-leads` maps `flashRecordings`; `renderFlashRecordings()` shows them under a "🎙️ Flash voice recordings" panel section (`#panel-recordings-section`, newest-first dated `<audio>` players). Flash itself captures + uploads the audio (its own gated `/api/recording` → Cloudinary since 2026-07-20; pre-7/20 rows point at Vercel Blob); the CRM only stores the URL + renders it. **Call transcript (2026-07-21):** Flash also uploads every call's TRANSCRIPT as text (Cloudinary raw) and postMessages `flash:transcript` — `crm.js saveFlashCallAsset` (a serialized promise chain — audio + transcript saves for one call must never interleave) POSTs it to `save-recording.js`, which MERGES `transcriptUrl` into the same callId entry (fills, never clobbers). `renderFlashRecordings` shows "📄 Transcripción · copiar enlace" under each player (`copyFlashTranscript` helper); the copy link is how Kevin sends a transcript to anyone. Full build notes: clairvo-clone CLAUDE.md §11 + memory `project_clairvo_clone_buildout`. **Panel-close = call ended (Kevin 2026-07-17):** every coach teardown (closePanel/overlay/Esc, coach ✕, lead switch in `populatePanel`) goes through `finalizeCoachSection()` — postMessages `flash:finalize` to the iframe (Flash stops the mic + submits the call = note/reminder/alerts, same as Detener) and blanks the src only after a 25s grace (`_coachBlankTimer`, cleared by `openFlashCoach`) so the submit/recording finish; NEVER call `resetCoachSection()` directly on a live coach. Re-opening the SAME lead leaves a live coach running (src leadId guard). Also 2026-07-17: `openPanel` adds `panel-expanded` by default — the lead panel opens in the WIDE view; ⛶ toggles it smaller.


## Lead Generation section (2026-09-10)

**What it is:** the third CRM bucket — every outreach prospect who replied, positive or negative, so Kevin never re-reads inboxes. Real-estate buyers stay in Real Estate; consulting-client campaigns are routed to Consulting.

**Data:** Airtable `LeadGen Leads` (`tblK1nzerZMMUajCF`) / `LeadGen Tasks` / `LeadGen Activity` (`tbl5yTjB0NTS8JugA`). Field vocab in `api/_leadgen.js`: `STATUSES` New / Contacted / Meeting Booked / Won / Lost · `SENTIMENTS` Positive / Question / Neutral / Not Now / Negative · `CHANNELS` Email / Facebook / LinkedIn / WhatsApp / LoopNet / Manual. Each lead keeps a running **Summary** (2-line conversation digest, rewritten on every reply), **Reply Count**, **Last Reply**, and the verbatim reply text lives in `LeadGen Activity` rows (type `Reply`).

**UI:** `crm.html` / `crm.js` "LEAD GENERATION" nav block (`switchView('leadgen…')`), table + filters (status / channel / campaign / sentiment), lead panel with editable sentiment + status pipeline, activity timeline, tasks. `crm.css` block tagged `LEAD GENERATION`.

**Lead panel parity (2026-09-10, Kevin: "make the layout the same, the font the same"):** `#leadgen-panel` is a structural clone of the RE `#lead-panel` — same section order (Contact → actions → Flash coach → Status/Sentiment/Owner → Summary → first reply verbatim → My Notes → Activity Log → Active Reminders → Set Reminder), same classes (`.panel-input`, `.panel-status-select`, `.panel-notes`, `.notes-history`, `.panel-activity-wrap`), ids prefixed `lg-`. **Contacted From** (`lg-contacted-from`) shows which of the 27 KPS / personal mailboxes the outreach went out from (`contactedFrom` on the lead; the Railway producers pass it). Font root cause of the old mismatch: `.panel-input` lacked `font-family: inherit` — fixed in `crm.css` (~line 909), so every panel input/select renders Inter. Notes = `LeadGen Activity` rows of type `Note` (My Notes); every other type → Activity Log.

**Lead Gen Reminders (2026-09-10):** nav item `leadgen-reminders` (`#leadgen-reminders-view`, badge `#leadgen-reminder-badge`) backed by `LeadGen Tasks`. Statuses map Open→Pending / Done→Completed / Skipped→Cancelled; types Call / Email / Meeting / Follow-up / Other; Owner is a closed set Kevin / Dylan / Rosa. Date **and time**: new Airtable field `Due` (dateTime, America/New_York, `fldirG6UiJYqsz8tK`) — Airtable's `update_field` cannot change a field's type, so `Due At` (date-only) stays as a legacy sibling. `create|update-leadgen-task` write both (`Due` ISO, `Due At` = first 10 chars); `_leadgen.js mapTask.dueAt = Due || Due At`; `get-leadgen-tasks` sorts by `Due`. Filters: status (default Open) + owner; panel section `lg-existing-reminders` lists the lead's open tasks with Edit / Done / Cancel.

**Flash on Lead Gen leads (2026-09-10):** the coach embed is generalized over two slots — `COACH_SLOTS = { re: {...'lead-panel'...bucket:'leads'}, lg: {...'leadgen-panel'...bucket:'leadgen'} }`, `coachSlot(slot)` treats a non-string (Event) arg as `re` so every legacy RE call site is untouched. The LG embed URL adds `&bucket=leadgen`; Flash (`clairvo-clone`) then reads/writes through `get-leadgen-leads?id=`, `get-leadgen-activity`, `get-leadgen-tasks`, `log-leadgen-activity` (Note), `create-leadgen-task`, `update-leadgen-task` (Done), `update-leadgen-lead` (status ladder upgrade-only New<Contacted<Meeting Booked<Won, dead-end→Lost; summary + `Next:`). `handleFlashMessage` routes `data.bucket==='leadgen'` (or an LG lead id) to `handleFlashMessageLG`, which logs recordings/transcripts as `Call` activity rows with the URL (`save-recording` is RE-only) and reloads leads + tasks. Not ported: `amendPriorNoAnswerNote` (no update-activity endpoint for LeadGen Activity).

**Email thread mirror (2026-09-10, Kevin: "all attachments … the whole email … any replies I do must be in the CRM"):** the reply net only captures the lead's reply text at ping time; `cloud-sender/thread_sync.py` (Railway worker, own daemon thread `_thread_sync`, every 10 min, `--cycle` = `newer_than:3d`; one-time `--backfill` = `after:2026/05/01`) sweeps All Mail on every box we send from (27 KPS + kevinpolermiami + kevinpoler1), X-GM-RAW `from:/to:/cc:` any Lead Gen lead email (from `get-leadgen-leads?limit=500`), and upserts each message as a `LeadGen Activity` row: outbound → `Email Sent` (agent Kevin), inbound → `Reply`; `Subject` (`fldzYwH4t0j2aqMjy`), `Mailbox` (`fldJtVzMFvCYT43gs`), `Message ID` (`fldwCaUCExictDjb4`), `Attachments` (`fldM08soqbuO2uVaG`, uploaded via `content.airtable.com …/uploadAttachment` base64, ≤4 MB each — Vercel's 4.5 MB body cap — bigger files get a `[Attachments not mirrored: …]` note in Details), `Details` = body with quoted history trimmed (`inbox_watch._body`). **Upsert:** `log-leadgen-activity` with `messageId` first looks for `{Message ID}=…` OR `FIND('[mid:…]',{Details})`; a hit is *enriched* (Subject/Mailbox/Message ID/Lead if empty, Details if longer, attachments by filename) instead of duplicated — so rows the reply net created get their subject + attachments filled in. Local seen-set `state/thread_sync.json` (60-day TTL) stops re-POSTs; the same message in two boxes collapses on Message-ID. **Per-lead read:** `get-leadgen-activity?leadId=` filters server-side on the lookup field `Lead Record ID` (`fldpLf71LwvOopBdK` → `LeadGen Leads.Record ID` formula `RECORD_ID()`, `fldmXn1JLxo6Ercmq`) because `ARRAYJOIN({Lead})` yields names, not ids, and `listAll` caps at 1,000 rows. **UI:** `loadLGActivity` renders any row with subject/messageId/attachments as an email card — subject, "Sent from / Received at <mailbox> · date", 160-char preview, **View full email** toggle (`.lg-email-full`, pre-wrap, 60vh scroll), 📎 chips linking to the Airtable attachment URLs (expire ~2 h, reloaded on every panel open).


**Ingest — `POST /api/agent/leadgen-reply`** (`api/agent/leadgen-reply.js`, Bearer `AGENT_API_TOKEN`):
1. Rule filter drops auto-reply / OOO / bounce / unsubscribe text unless `force:true`.
2. **Idempotency:** if `messageId` is given, `[mid:<id>]` is stamped into the activity Details and a `FIND()` pre-check over `LeadGen Activity` + `Consulting Activity` returns `{ok:true, skipped:'duplicate'}` on a repeat. Every hook passes one, so the Railway double-sweep (inbox_watch + smtp_sender read the same KPS mailboxes) can't double-write.
3. **Consulting router:** campaign/company regex (Plaza San Miguel / Atrio / Mara / CSC / Tamamra / Venezolana …) → writes a `Consulting Activity` row on the matching company and returns `routed:'consulting'`. Keystone/Abrams stays in Lead Gen (Kevin 2026-09-10).
4. Claude `claude-sonnet-5` tags sentiment + rewrites the summary + proposes `next_step`; `sentiment` in the body overrides the classifier.
5. Upsert by `sourceLeadId`, then email. Optional `status` sets the pipeline stage but never downgrades Won / Meeting Booked; new rows default to `New`.
